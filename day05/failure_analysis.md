Failure Analysis
Case 1

JD：

负责 LLM 应用和知识库问答系统建设

真实标签：

1（AI岗位）

预测标签：

0（非AI岗位）

可能原因：

关键词没有在训练集中充分出现
文本长度较短，包含的有效特征较少
训练数据规模较小，模型学习到的 AI 岗位特征不足
标签定义可能存在边界问题（“知识库问答系统建设”同时涉及应用开发和传统软件系统开发，容易混淆）
TF-IDF 基于词频统计，无法理解“LLM应用”“知识库问答系统”等词之间的语义关联
Case 2

JD：

基于 LLM 搭建文档摘要、信息抽取业务模块

真实标签：

1（AI岗位）

预测标签：

0（非AI岗位）

可能原因：

“LLM”虽然是明显 AI 关键词，但训练集中类似表达不足，导致模型没有形成稳定判断依据
文本较短，仅包含少量关键词，TF-IDF得到的特征维度有限
训练样本数量较少，模型泛化能力不足
“文档摘要”“信息抽取”也可能出现在普通软件开发任务中，导致分类边界不明显
TF-IDF无法理解“基于 LLM 搭建”和“AI应用开发”的深层语义关系，只能依赖词语是否出现
Case 3

JD：

开展大模型微调、提示词工程效果调优

真实标签：

1（AI岗位）

预测标签：

0（非AI岗位）

可能原因：

“大模型微调”“提示词工程”等专业术语在训练数据中的覆盖不足
数据集规模较小，模型没有学习到 AI 岗位的完整关键词组合模式
文本过短，缺少更多辅助判断信息（例如 RAG、Agent、Python、Embedding 等关键词）
标签数量有限，模型可能偏向预测样本数量更多或特征更明显的类别
TF-IDF无法理解“大模型微调”和“AI算法岗位”之间的语义联系，只能判断词频特征
总体 Failure Analysis 总结

本次错误案例均属于：

真实为 AI 岗位，但模型预测为非 AI 岗位（False Negative）

主要原因：

训练数据规模较小

当前数据集样本数量有限，模型学习到的 AI 岗位模式不足。

文本特征不足

JD 通常只有一句话，缺少更多上下文信息，导致 TF-IDF 获得的有效特征较少。

TF-IDF 方法存在局限

TF-IDF 主要根据词频和关键词匹配判断：

能识别：
RAG
Python
Agent

但无法真正理解：

“LLM应用开发” ≈ “大模型岗位”

这种语义关系。

类别边界不够清晰

一些岗位描述同时包含：

软件开发
数据处理
AI应用

单纯依靠关键词容易产生误判。

后续优化方向
增加更多标注数据
丰富 JD 文本长度
使用更强文本表示方法（如 Embedding）
使用语义模型替代单纯 TF-IDF
优化标签定义，例如进一步划分：
AI应用岗位
算法岗位
后端岗位
数据岗位
